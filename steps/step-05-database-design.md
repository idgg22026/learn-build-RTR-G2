# Step 5 — Design the database

## Goal
You have an **ERD** for the whole app and the first real migration (`rooms`) runs.

## You will learn
- Designing tables from the feature list
- Migration rules used in this project: **one change = one new migration**, money as `decimal`/integer riel,
  `softDeletes()` for records that invoices still point to
- Snapshot columns (an invoice copies the numbers it used)

## The ERD (main tables)
```
users ──(tenant_id)──► tenants ◄──(room_id)── rooms ──► room_items
                          │                     │
                          ├──► tenant_documents  ├──► main_meters ──► main_meter_readings
                          ├──► tenant_occupants  │
                          ├──► meter_readings ◄──┘   (one row per tenant, room, month "2026-11")
                          ├──► invoices ──► invoice_items, invoice_payments, payment_proofs
                          ├──► move_in_payments, deposit_transactions, deposit_settlements
                          ├──► move_out_notices
                          └──► maintenance_requests
settings (key, value JSON)   expenses, recurring_expenses   announcements   activity_logs
```

| Table | Key columns | Why |
|---|---|---|
| `rooms` | `room_number` unique, `rent_price` decimal(10,2) USD, `status` enum | the thing you rent |
| `tenants` | `room_id`, `move_in_date`, `move_out_date`, `status` active/moved_out | who lives there |
| `meter_readings` | `tenant_id`, `room_id`, `period` char(7), previous/current/usage/amount | monthly utilities |
| `invoices` | `invoice_number`, `period`, copies of rent, rate, usage, `total_riel`, `status` | **frozen** bill |
| `settings` | `key`, `value` | exchange rate, tiers, contract text |

> **Main point — snapshot:** the `invoices` table stores `rent_usd`, `exchange_rate`, `electric_rate`… at the time
> it was made, so changing a room's price later never changes an old invoice.

## Do it
```bash
docker compose exec laravel php artisan make:migration create_rooms_table
```
```php
public function up(): void
{
    Schema::create('rooms', function (Blueprint $table) {
        $table->id();
        $table->string('room_number', 20)->unique();     // e.g. A101
        $table->unsignedTinyInteger('floor')->nullable();
        $table->string('type', 50)->nullable();           // e.g. Single, Double
        $table->decimal('rent_price', 10, 2);             // monthly rent (USD)
        $table->enum('status', ['available', 'occupied', 'maintenance'])->default('available');
        $table->text('description')->nullable();
        $table->timestamps();
        $table->softDeletes();
    });
}

public function down(): void
{
    Schema::dropIfExists('rooms');
}
```
Later the project needed `owner_use` status, EDC account and main-meter links. It did **not** edit this file;
it added new migrations (`update_room_number_unique_on_rooms_table`, `utility_improvements`, `edc_electricity`).
Do the same in your projects.

Now the tenants table (`make:migration create_tenants_table`):
```php
Schema::create('tenants', function (Blueprint $table) {
    $table->id();
    $table->string('full_name', 100);
    $table->enum('gender', ['male', 'female', 'other'])->nullable();
    $table->string('phone', 20);
    $table->string('email', 100)->nullable();
    $table->string('id_card_number', 50)->nullable();
    $table->string('address')->nullable();
    $table->string('emergency_contact_name', 100)->nullable();
    $table->string('emergency_contact_phone', 20)->nullable();
    $table->foreignId('room_id')->nullable()->constrained('rooms')->nullOnDelete();
    $table->date('move_in_date')->nullable();
    $table->date('move_out_date')->nullable();
    $table->enum('status', ['active', 'moved_out'])->default('active');
    $table->text('notes')->nullable();
    $table->timestamps();
    $table->softDeletes();
});
```
```bash
docker compose exec laravel php artisan migrate
```

## Check
`php artisan migrate:status` lists both migrations as **Ran**; phpMyAdmin shows the columns.

## Practice
Write the migration for `meter_readings` yourself: `room_id`, `tenant_id`, `period` (char 7, e.g. `2026-11`),
`electric_previous`, `electric_current`, `electric_usage` (decimal 10,2), `electric_rate` and `electric_amount`
(unsigned integers in riel), the same for water, `total_amount`, `read_at`, `notes`, and a unique index on
`['room_id', 'period']` (one reading per room per month). Compare with
`2026_11_03_162718_fix_meter_readings_table.php` in the original project.
